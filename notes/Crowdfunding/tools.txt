Block Editor
    Smart blocks that can be brought to life by plug-ins.
    Blocks have a class name which is looked up in the registry.
    Multiple plug-ins can register for the same block.
    Could have multiple plugins active at once.
    Block data is stored in js dict in block.
    Block plug-ins can share the same data.
    Use Lasloesque constraints and data binding to bind the attributes of the plug-in class to the shared json dict key/value pairs. 
    Use constrints instead of MVC to automatically synchronize multiple views and editors.
    Like Unity3D components, but better because it has data binding to arbitrary keys of the shared dict.
    Keep a parallel dict of the events (insteaod of prefixing with _ in the data dict). 
    Best to keep the persistent data separate from the runtime data.
    The data dict is loaded and saved literally and edited in place.
    Leave alone keys you don't understand, they belong to other plug-ins that might not be loaded.
    So plug-in editor could be removed from the runtime system the only need view-only versions of the block, and in the editor you can add and remove (or enabled and disabled) special editors or views of various types. 

Make an object in the world that is a "field projector" that applies a simulation of some sort to a region of the world.

Blocks in the world don't usually have any simulations running them, but you can create objects the world that run various simulations the blocks of the world. 

Cellular automata rules like "eco," using lava and ice as water and land, with some other cool looking blocks for firey "brain's brain" critters on lava and crystaline "life" critters on ice).

Plop these cool simulation objects into the voxel world and configure and script them to do cool stuff.

They create and run simulation components on blocks of a region of the world.

Multiple fields can overlap the same blocks, and they can be synchronized in sequence, or each run at its own clock rate and phase.

They share data with each other through the "layers" of named properties they create in the block dictionaries. 

Configure the speed it runs (ticks per second), and the box it effects. 

Fields can operate on single blocks or any pattern or subset of blocks in the area.

they can be used as editing tools, probes or agents, that can move around or change shape if they like. 

Running simulations could cost "energy" or "mana" according the the speed and enumber of components running.

Script the simulation projectors as well as the block components it creates.
